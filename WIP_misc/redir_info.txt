Bash Redirection Reference Sheet

In Bash (and Minishell), commands typically communicate via two main data streams:

    Stdin (Standard Input): Data flowing into the command (default: keyboard).

    Stdout (Standard Output): Data flowing out of the command (default: terminal screen).

Redirection operators change the source or destination of these streams.
1. Input Redirections (Data entering the command)
< (Input Redirection)

Function: Feeds the contents of an existing file into the command's Stdin.

    Logic: "Don't read from the keyboard; read from this file instead."

    Minishell Action: Open the file in O_RDONLY mode. If the file doesn't exist, it is an error.

    Example: Search for "root" inside the password file.
    Bash

    grep "root" < /etc/passwd

<< (Heredoc)

Function: Reads input from the command line (keyboard) until a specific Delimiter is typed.

    Etymology: "Here Document". The document is not in a distant file; it is located right here in the code/terminal.

    Minishell Action: Read lines from Stdin endlessly until the line matches the delimiter. Store the input (usually in a pipe or temporary file) and then feed it to the command.

    Example: Pass a multi-line message to cat without a file.
    Bash

    cat << EOF
    This is line 1
    This is line 2
    EOF

2. Output Redirections (Data leaving the command)
> (Output / Truncate)

Function: Redirects the command's Stdout to a file, overwriting it.

    Logic: "Don't print to the screen; write to this file. If the file has data, wipe it clean first."

    Minishell Action: Open in O_WRONLY | O_CREAT | O_TRUNC.

    Example: Save a directory listing to a file (erasing previous content).
    Bash

    ls -la > filelist.txt

>> (Append)

Function: Redirects the command's Stdout to a file, adding to the end of it.

    Logic: "Don't print to the screen; add this to the bottom of the file. Do not delete existing data."

    Minishell Action: Open in O_WRONLY | O_CREAT | O_APPEND.

    Example: Add a new line to a log file.
    Bash

    echo "Server started at 12:00" >> server.log

Implementation Note for the Parser

For tokens_to_array (and the Executor later), treating these correctly requires two steps:

    The Filter (Parser): These operators and their filenames are NOT command arguments.

        Structure: [CMD] [ARG] [OP] [FILE]

        Correct Argument Array: {"CMD", "ARG", NULL}

        Rule: When iterating tokens, if you see an operator (<, >, <<, >>), you must skip the operator AND the next token (the filename/delimiter).

    The Execution (Executor): The Executor will loop through the generated file_list to apply these redirections (using dup2) before running the command.
